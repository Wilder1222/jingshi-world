## 版本和执行前检查

沿用项目已明确的 **MJ V8.2 网页版**。本包于2026-09-08核对官方说明：V8.2已可用，V8系列通过Edit Model处理引用，不能照搬V7的Omni Reference参数。[版本说明](https://docs.midjourney.com/hc/en-us/articles/32199405667853-Version)、[Omni与Edit区别](https://docs.midjourney.com/hc/en-us/articles/36285124473997-Omni-Reference)。

基础参数尾为 `--ar 比例 --v 8.2 --raw --s 75 --c 0`。这是本项目的起始设置，不是官方推荐数值或最佳画质保证；不附`--q`、`--hd`、`--oref`、`--cref`，不混用多重提示词权重。参数放在描述后。[官方参数表](https://docs.midjourney.com/hc/en-us/articles/32859204029709-Parameter-List)。

每次执行前由你检查网页当前状态：

1. 模型确为V8.2；基线关闭Personalization和Moodboard，并核对实际提交不含遗留profile代码，清除上一任务遗留引用；初轮不用未批准的`raw/`参考图。
2. 确认画幅、Raw、Stylize、Chaos与本项一致。账户默认设置、订阅权限和实际页面未由本轮检查，不能把提示词当作已执行验证。
3. 无前置的基础项直接用纯文字；有前置的项先选择父母版，在网页版编辑／引用流程加入该实际图片。任务编号不是图片地址，不能粘贴代替引用。
4. 为每张输入说明用途：身份、衣装或空间。只用自己有权使用的图片；不擅将现实人物照片、外部作品或旧参考当已授权角色脸。
5. 导出实际原图并记录真实任务ID、完整提示词、实际模型与参数、Seed（如可取得）、输入图片、尺寸、日期和选版意见。Seed不替代身份引用，提示词也不保证精确复现。

MJ投影仅作交接；用户现已要求资产生成，实际另通过内置imagegen执行并记录工具，不能把该产物写成MJ生成。英文描述按可见主体、衣装、材质和光线组织，不把剧情背景塞成画面中的汉字说明牌。[提示词原则](https://docs.midjourney.com/hc/en-us/articles/32023408776205-Prompt-Basics)。

## 选版门槛与可回退顺序

- 身份：正脸先定骨相；侧脸与四分之三脸只变视角。不要把两张不同脸各取优点却仍声称同一角色。黄祁先做无遮脸身份，雨帽面巾另派生。
- 衣伤：顾砚自身左肩受伤；原顾与今顾同一浅灰干衣、同一包扎。黄祁只有湿衣、侧脸短露和戒备，无新增伤口或血迹。所有左右均指角色自身。
- 群像：五卒各有独立脸、常服和磨耗铜片；韩青计入五人，顾砚不计入。杨舟只有声位，不建现代露脸母版。
- 空间：先对门、窗、桌、通路，再谈漂亮构图。一个空景只能证明一个机位，不能把其余方向自动算作完成。
- 道具：先形制后文字；P06冒役领条、P07租单、P08收件纸各自独立；P04真票始终留府。P09完整杯选定后派生碎片，不重新随机抽杯型。
- 风格：身份基线无新增高光扩散。`MB-TEST-C01-BLOOM`保留为选做的极弱局部光学溢出对照，只用同一张已核正脸；无金色光晕、梦幻泛光或暖黄罩染，不磨皮、不改脸衣机位，不作后续生产必需前置。
- 组合：通过单项后再做人景测试，检查光向、头身比、扶持侧、门院视线；通过静帧不等于通过动作、配音、连贯剪辑或安全审阅。

穿越只通过表演差异与观众记忆呈现；不做灵魂叠影、现代字码眼睛、宿命光束、系统界面。前三集没有女主定妆出场、程隐入镜、遗信P13、失世场面或天人领域。

## 文件使用与维护

`视觉任务源.json`和`补充任务源.json`为作者维护的非规范工作草案；`生产任务.json`是带源文件校验值的派生计划，**不是媒体入库凭证**。`actual_file`仅在实际媒体入库后填写：当前3项FACE及顾砚／顾伯／杜长庚FULL已选，顾砚／杜长庚FULL-BACK、W1-01／05为生成候选，其余为空。生成记录原地维护于媒体登记，模板不是实际选版证明。

任务编号`MB-*`与`POST-*`只管理制作，不重排剧情C/S/P编号，不代表新增世界观人物或器物。完整清单列出来源资产、使用场次、依赖、验收点和提示词。场次关联供检索；具体“露脸／仅声响／仅局部”的呈现仍以台本和场次notes为准，不能因一项关联场次就强加特写。

维护命令（在项目根目录）：

```text
python 工具/前三集生产准备.py build
python 工具/前三集生产准备.py check
```

修改剧情或源卡后先完成项目既有同步，再重建本包。检查会核对任务编号、依赖闭环、16场完整预备覆盖与前三发行集11场映射、71镜连续帧窗、20张独立身份脸、首批20项服装图、禁用资产和派生件新鲜度；它不替代人工判断脸是否一致或画面是否好看。

本轮使用CineWeave的“世界—剧情—人物／资产”流程，将身份、衣伤、表演、空间和服务参数拆开，并保留未选版与未验证状态；这也是本包不把提示词数量当作资产完成度的原因。
